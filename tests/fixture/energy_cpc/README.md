# Energy reference fixtures (#1163)

These describe the **climate-driven component** of energy supply and demand,
not actual generation or load. No energy implementation exists yet. The reference
tests xfail only when their module/function is absent (#1164, #1165); numerical,
shape, missing-mask and unrelated import failures are never suppressed.

## CPC first: explicit single-base degree days

The maintainer selected CPC first. `reference.json` transcribes section 1 of
[NOAA CPC's degree-day explanation](https://www.cpc.ncep.noaa.gov/products/analysis_monitoring/cdus/degree_days/ddayexp.shtml),
retrieved 2026-10-17: mean daily temperature is `(Tmax + Tmin) / 2`, with a
65 °F base for heating and cooling. The published CDD inputs are
`[67,65,70,74,78,65,68]` °F, outputs `[2,0,5,9,13,0,3]` °F day, total **32 °F day**.
This seven-day worked example is authoritative reference evidence, not observed
station data. The source excerpt normalizes HTML entities and whitespace; the raw
page is not committed, but its SHA-256 is retained for audit. Refresh by retrieving that page, comparing section 1,
and explicitly updating the transcription, retrieval date and checksum.

Tests convert temperatures as `(F - 32) * 5/9`, including the exact base
`(65 - 32) * 5/9` °C, and **differences** as `F_day * 5/9`, without an offset.
No rounded 18 °C base is substituted. Original integer values are exact;
`rtol=0`, `atol=1e-12` °C day permits conversion roundoff only.

The separate `specification_cases` are hand-calculated synthetic examples, **not
published CPC numbers**. They cover heating/cooling activation, equality, a missing
day, and EDD = HDD + CDD with equal, distinct and overlapping bases. The synthetic
overlap case makes both terms positive to distinguish their sum from their maximum;
it is not a CPC product convention. EDD is an algebraic identity, not an independent
external oracle. JSON `null` means NaN; zeros and missing masks
must match exactly. No real timestamps, calendar, spatial weighting, Calibration
Period or accumulation apply: each row is an independent daily mean.

Pending calls use `base_temperature` for HDD/CDD and `heating_base_temperature` /
`cooling_base_temperature` for EDD, always explicitly in °C. These fixtures choose
**no public default**. C3S's threshold/reference pairs cannot be represented by a
single base. C3S boundary rules, population-weighted extraction, and monthly
normalization remain outside this fixture; #1164 owns any later contract extension
or default decision. See `docs/research/energy-oracle-survey.md`.

NOAA/NWS/CPC is the source of the published numbers, which are public-domain
information under [NWS terms](https://www.weather.gov/disclaimer) (no section-1
exception marked). Synthetic additions and unit conversions are ours, not official
NOAA products. No NOAA/NWS endorsement is implied.

## Independent wind-profile outputs

The sibling `../energy_wind/reference.json` contains outputs actually generated by
**xclim 0.62.0** (`wind_profile`, `method="power_law"`, explicit `alpha`) and
**windpowerlib 0.2.2** (`logarithmic_profile`, `obstacle_height=0`). Their upstream
commits, whole source-file SHA-256 hashes and numerical dependency versions are
recorded in that file. Source files were checked against their pinned release tags
before execution. Synthetic speeds span 0–12 m s⁻¹ and a missing value, reference
and hub heights 10–150 m, power exponents 0, 1/7, 0.2 and 0.3, and roughness
lengths 0.03, 0.1 and 1 m. Heights and roughness are metres. Cases include upward,
downward, zero-exponent and identity-height transforms.

Regenerate manually in an isolated script environment (not a project dependency):

```bash
uv run --python 3.12 scripts/prepare_energy_wind_fixtures.py
```

The script rejects mismatched provider versions/source hashes and validates calm,
identity, shape and missing values, including under optimized Python. It stages both
JSON files before publishing their directory and restores the previous pair if the
swap fails. An uncatchable interruption between directory moves can leave
`.energy_wind-backup`; the next publication recovers it. It imports neither
`climate_indices` nor its future implementation. CI consumes committed JSON and
requires neither provider. xclim's optional matplotlib-setup warning does not affect
the numerical calls. Synthetic inputs and numerical outputs contain no copied
implementation code; the reference software is Apache-2.0 (xclim) and MIT
(windpowerlib), not new library dependencies.

These are **independent-implementation comparisons**, not validation against
observed hub-height wind. Tolerance is `rtol=0`, `atol=1e-12` m s⁻¹ for ordinary
float64 arithmetic, with exact calm, identity-height and NaN behavior. Recovering
alpha from the generated 10/100 m pair is separately labelled consistency evidence;
it does not turn a round trip into independent validation. Calm pairs are excluded
from the log-ratio calculation. No measured library agreement is claimed until
#1165 exists.

## Integrity and scientific gate

Each directory's schema-valid `provenance.json` hashes that directory's canonical
`reference.json` bytes directly. `tests/test_energy_reference.py` checks hashes in
the default suite; the existing provenance protocol checks both schema records.
To run the pending contracts explicitly:

```bash
uv run pytest tests/test_energy_reference.py -m validation -rx
```

Maintainer confirmation of the CPC transcription and wind generation/redistribution
is required **in the fixture PR** before the scientific gate is satisfied. This
fixture does not claim that confirmation. #1180 owns the eventual published energy
validation inventory and API docs, once the implementations exist.
